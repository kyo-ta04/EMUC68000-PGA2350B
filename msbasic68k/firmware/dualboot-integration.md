# MS-BASIC 68K デュアルブート統合メモ

EMUC68000-PGA2350B ファームウェアに MS-BASIC 68K 移植版を
ブートメニュー選択式で組み込むための成果物と手順。

配置は **$0 版**（主力ビルド `msbasic68k.bin`）を使う。$30000 配置は
「EhBASIC がホストとして居て `CALL $30000` で入る」前提の着陸ゾーン住所であり、
ファームから直接ブートする場合はその制約が消えるため。$0 版イメージは
先頭に自前のリセットベクタを持ち、ファーム側は 0 番地へ置くだけでよい。
また $0 版は M1〜M5d の全テストスイートが走った最も実績のある構成で、
sim では EhBASIC が存在しない環境でリセットベクタから単独ブートして
全チェックを通過している（＝エントリ $194 は EhBASIC の存在を前提にしない）。

なお $30000 版（`msbasic68k-hw.bin`、BSD sum 5542）は、EhBASIC 上のローダから
`CALL $30000` で入る従来経路用として引き続き残る。本統合とは独立に使える。

## 変更点一覧（EMUC68000-PGA2350B.c）

1. **`#include "msbasic68k.h"` を追加**（ehbasic.h の直後）。
2. **定数 1 つを追加**：`BOOT_MENU_WAIT_MS 3000u`。
3. **`boot_menu_msbasic_selected()` を main() の直前に追加**。
   USB CDC から 3 秒間だけキーを待ち、最初に押されたキーで即決する。
   使っている API（`getchar_timeout_us` / `make_timeout_time_ms` / `time_reached` /
   `sleep_ms` / `stdio_flush` / `printf`）は全て既存ファイル内で使用済みのものだけ。
4. **main() のイメージロード部を分岐化**：
   - MS-BASIC 選択時：`load_to_memory(MSBASIC68K, msbasic68k_size, 0x0000)` で
     0 番地へ置き、`Load MS-BASIC 68K` と表示。それだけ。
     イメージ先頭のリセットベクタ（SSP=$00030000、PC=$00000194）がそのまま使われるため、
     **ファーム側でベクタを書く処理は無い**。
   - それ以外：従来の `selected_test()` → `load_to_memory(..., 0x0000)` を**一字も変えず**に実行。
   - 分岐の後（RESET-ON、Core1 の bus_emu 起動、reset_off のクロック設定＝6MHz、
     uart_task）は両経路で完全共通。bus_emu のアドレス解釈（& 0x3FFFF の 256KB ミラー、
     ACIA は全アドレス判定）にも一切手を入れていない。

CMakeLists.txt の変更は 1 行：`add_executable(... ehbasic.c msbasic68k.c)`。

## メニュー仕様

- 起動バナー（`Start..`）の直後、イメージロードの前に表示される：

  ```
  Boot menu: [M] MS-BASIC 68K  /  [E] EhBASIC (default)
  Press M within 3s for MS-BASIC:
  ```

- **'M' / 'm'** → MS-BASIC をロードして起動。
- **'E' / 'e'・その他のキー・3 秒タイムアウト** → 既定の EhBASIC（従来動作）。
  USB が未接続のまま起動した場合も、キーが来ないので自動的に EhBASIC になる。
- 押されたキーはエコーされ、タイムアウト時は `(timeout)` と表示される。
- EhBASIC 経路の既存挙動への影響は「起動時に最大 3 秒の待ちが増える」だけ。
- 物理リセット（または電源再投入）で再びメニューが出る。MS-BASIC からの離脱は
  従来通りリセットのみ（MS-BASIC は EhBASIC へ戻らない設計）。

## イメージ配列の検証結果（こちらで実施済み）

- 実測：`msbasic68k.bin` は **15,492 バイト、BSD sum 32584**
  （プロジェクト定義：16bit 右ローテート＋加算）。先頭 8 バイトは
  `00 03 00 00 00 00 01 94` ＝ SSP=$00030000 / PC=$00000194 で仕様通り。
  ※ $30000 版 hw.bin の sum 5542 とは別物なので取り違え注意。
- `gen_msbasic68k.py` の自己検証：生成した C 配列を抽出して `msbasic68k.bin` と
  **バイト完全一致**、BSD sum 32584 を確認。
- 追加の独立確認：ホスト gcc で `msbasic68k.c` をコンパイルし、C 側で size と
  BSD sum を再計算 → size=15492、sum=32584、先頭 4 バイト `00 03 00 00`。
- 単独ブートの実績：sim（Musashi）で M1〜M5d の全スイートが、このイメージを
  RAM $0 に置いてリセットベクタから直接起動する形で通過済み。EhBASIC は介在しない。
- **ファーム本体のビルド検証は Kyo 側**：この作業環境には Pico SDK /
  arm-none-eabi ツールチェーンが無いため未実施。パッチ追加コードは既存ファイル内で
  使用済みの API のみで構成し、括弧バランスも元ファイルと同差分であることを確認済み。
  また diff がクリーンなコピーへ `patch -p1` でそのまま当たることを検証済み。

## Kyo 側のビルド／書き込み手順（要点）

1. 実ファームのソースツリーに `msbasic68k.c` / `msbasic68k.h` をコピーする。
2. `EMUC68000-PGA2350B.c` と `CMakeLists.txt` にパッチを当てる
   （ツリーがクローンと同一なら `patch -p1 < EMUC68000-PGA2350B-dualboot.diff`、
   兄弟構成なら本メモの「変更点一覧」を対応箇所へ手で反映）。
3. 通常通り Pico SDK でビルドし、uf2 を書き込む（手順は従来と同一）。
   FLASH 増加分は 15,492 バイトのみ。

## ベンチ確認項目と予測

| # | 操作 | 予測 |
|---|---|---|
| 1 | 電源投入→何も押さず 3 秒待つ | `(timeout)` 表示の後、従来通り EhBASIC が起動（`260628 Bytes free`、Version 3.54 バナー） |
| 2 | 電源投入→3 秒以内に `E` | 即 EhBASIC 起動（#1 と同じ） |
| 3 | 電源投入→3 秒以内に `M` | `Load MS-BASIC 68K` → RESET-OFF → `### COMMODORE BASIC ###` ＋ `61440 BYTES FREE` ＋ `READY.` |
| 4 | MS-BASIC で `PRINT 2+3*4` | ` 14 `（NUMSPC=$20 仕様） |
| 5 | MS-BASIC で ASCIIART.BAS を RUN | 約 **110 秒** @6MHz で完走し絵が golden と一致、READY. に戻る。実行コードは $30000 版と同一で配置だけが違うため、実機秒は hw 版の実測（約 110 秒）と同等のはず（Musashi サイクル換算の約 220 秒ではない） |
| 6 | 長い RUN 中に CTRL-C | `Break in line n` で停止、CONT で再開可 |
| 7 | MS-BASIC 中に物理リセット | ファームの起動バナーに戻り、再びブートメニューが出る |
| 8 | TEST_SELECT を変えたビルド（任意） | EhBASIC 既定経路は selected_test のまま（メニュー無効化ではなく既定側に乗る） |

## 補足・既知の割り切り

- メニュー待ちの間に届いたキー入力はメニューが消費する。`M` の後にターミナルが
  CR/LF を送る設定だと、その分は起動後の BASIC 側への空行入力として流れる（無害）。
- 起動直後 2 秒の USB 接続待ちの間に押されたキーもメニューの入力として拾う
  （CDC バッファに残るため）。意図しない選択が気になる場合は、バナーを見てから押すこと。
- MS-BASIC のライセンスは原典 microsoft/BASIC-M6502 の MIT。ファームに組み込む際は
  帰属表示（MIT notice）をファーム側のドキュメント等に残すこと。
