# M3 結果メモ — 式評価＋変数＋FP中核＋FOR/NEXT

2026-11-18。対象: `msbasic68k.asm`（8,361 バイト、$0000–$20A8）、検証: `run_m3.py`。
判定: **M3 PASS**（全31チェック＋M1/M2 回帰 PASS、分岐先チェッカ 0 件不良）。

## 実装範囲

- **FAC/ARG と ZP レイアウト**: 原典の ZP 割当を ZP ミラー（$010000 台）に準拠配置。FAC $10107（仮数 +1..+4、FACOV = FAC+5、FACSIGN = FAC+6）、ARG $1010F、RESULT $10123、FBUFF $1012D 等。値はメモリ常駐のまま（レジスタ化しない）。
- **数学パック中核**: FSUB/FADD、FMULT/FDIV、MOVMF 系移動、SIGN/SGN/FLOAT/NEG/ABS、FCOMP、QINT/INT、FIN（文字列→FP）、FOUT（FP→文字列）。原典のアルゴリズムと丸めを移植。FP 形式は 5 バイトパック（指数1＋仮数4、ADDPRC==1）。ポイント:
  - ROUND_FAC は拡張バイトを先にシフトし、シフト前の拡張 ≥ $80 のときだけ増分。
  - NORMALIZE は原典の「32 回シフトでゼロ化」癖まで再現。
  - MUL10 は FMULT×10 ではなく原典通り（ARG へ丸めコピー→指数+2→FADD→指数+1）。DIV10 は定数 10.0 による FDIV。
  - FMULT は乗数を LSB 側から消費し、加算のキャリーアウトを 41 ビット蓄積器へ回転入力。FDIV は商ビットをちょうど 34 本生成。
  - FCOMP の最終バイト同点判定は FACOV > $7F。INT(−3.7) = −4 を golden で確認。
  - FOUT は符号文字（' ' / '-'）を FACSIGN 自体へ格納し、CON_BILLION でスケール、DECTBL による桁生成、先行ゼロなし（`.333333333`、`-.5`、`.05`）、指数サフィックスは常時 2 桁（`1E-05`、`1E+10`）。
- **式評価**: 原典の優先順位テーブル（MATPREC）による状態機械評価器。数値リテラル、FP スカラー変数、+ − * /、単項マイナス、括弧、比較演算子（> =1、= =2、< =4 のマスク方式、結果 −1/0）、関数 INT/ABS/SGN。関係演算の右辺評価は PERFORM2 経由。
- **変数**: FP スカラーの検索・作成（VARTAB、名前 2 文字＋型識別は原典準拠）。未定義変数は 0。LET（暗黙の LET 含む）。
- **PRINT の数値対応**: FOUT 表示（正数に先行スペース）、';' 区切りと末尾 ';'（改行抑制）、',' 区切り（ゾーン整形は簡易。原典準拠化は M4）。文字列リテラル混在可（TEMPST 記述子の軽量経路）。
- **FOR/NEXT**: STEP 対応（1 固定でない）、ネスト対応。フレーム形式は下記「原典から外れた点」2 を参照。

## 原典から外れた点

1. **FADD の内部モデル**: 原典の拡張バイトの踊りを再現せず、40 ビット＋スティッキーのクリーンなモデルで実装。差は拡張バイトの塵の範囲に confined され、照合した全値に影響なし。
2. **FOR フレームの管理**: 原典は生スタックのバイト走査でフレームを探すが、68K では戻りアドレスと混在するため再現できない。固定 44 バイトの CPU スタックフレーム＋ FORSP 連結リストで追跡（フレーム内容と NEXT の終了判定＝FCOMP 結果 − ステップ符号バイト == 0 は原典通り）。これに伴い、JSR ディスパッチの戻りアドレスを FORRET/NEXTRET（ZP）に退避し、FORH/NEXTH の出口は RTS でなく JMP にした（原典は JMP ディスパッチなのでこの問題自体がない）。NX_EXIT のフレーム回収は `LEA 44(A2),SP`（原典の TXS 相当）。
3. **FOUT の桁ループ**: 原典の符号交互加算ではなく |entry| の繰り返し減算。生成桁は同一。
4. **FIN の先行 '-'**: FIN 内（SERLEN）でなく FRM_ELEMENT 側で NEGOP により適用。外部挙動は同一（FINSGN 枠は未使用）。
5. **PERFORM2 の ARGEXT**: スタック済み被演算子の拡張バイトはフレームに含まれず、ARGEXT := 0 とする。
6. **要判断-1（OUTSP の末尾バイト）**: 数値 PRINT の末尾空白について、CBM BASIC 2（画面デバイス）は $1D を出すが、本移植は汎用 v1.1 対象と同様に $20 を出す。run_m3.py では $1D→$20 に正規化して比較し、今回のセッションでは 29 バイトを数えた。**どちらが正かは未判断** — v1.1 実機仕様の確認待ちとして切り分ける。
7. **^（累乗）**: FPWRT 未実装のため M3 では ?SN ERROR スタブ。ASCIIART は使わない。実装するかどうかは M5 までに判断。
8. **未実装（M4/M5 へ）**: 配列、文字列連結（CAT）、文字列式の本格経路（M3 はリテラルの TEMPST 軽量経路のみ）、GOSUB/RETURN、IF 本体（評価器側の比較は用意済み）。

## 踏んだ問題

1. **asm68k-py の短分岐サイレント切断**: 範囲外の `Bcc.S`/`BRA.S` が変位の下位バイトだけで符号化されていた。全 389 箇所の `.S` を無サイズ化し、命令境界チェッカを導入（ボス段の ASM.BAS 検証にも転用価値あり）。
2. **asm68k-py の変位 0 分岐バグ**: 直後命令への BRA（変位 0 ＝ワードエスケープ）を、変位フィールドにターゲット先頭ワードを書いて符号化。実在 2 箇所（SGNFN、DZERR）はフォールスルー化して回避。
3. **68000 にメモリ対象バイトシフトはない**: `ASL.B FACOV` 等はワード演算として実行され FACOV:FACSIGN を壊した（当初疑った「シミュレータの RMW 癖」は検証の結果、誤り — sim/Musashi が正しかった）。4 箇所をレジスタ経由シフトに修正。
4. **ADDX/SUBX のメモリソース形式は存在しない**: アセンブラがレジスタ形式に化けて各バイトが 2 倍化（24+6 の FADD が幻のキャリー経路へ）。FADD の加減算 8 箇所を D1 経由に修正。
5. **EOR のメモリソース形式は存在しない**: SGNCPR が常時 0 になり `PRINT -7/2` が ` 3.5 ` になった。4 箇所を D1 経由に修正。
6. **MOVE が CCR を書き換える罠**: 6502 原典がフラグ存続を前提にする箇所（PRINTH のプライミング判定、PERFORM2 の LSR キャリー判定、FIN の桁退避）で同型のバグ。M2 の FNDLIN と同じ教訓。
7. **レジスタ退避漏れ 3 件**: FIN のスケール回数カウンタ D1 を FDIV の剰余 D1 が破壊（`PRINT 1.5`→0、`PRINT 3.7`→オーバーフロー）。NEXTH のフレームポインタ A2 を FADD_CORE が破壊。FE_UF の関数ポインタ A2 を引数評価が破壊（`PRINT INT(3.7)` が ARG 領域へ飛ぶ）。いずれも呼出側で push/pop して解決。
8. **関係演算のオフバイワン**: 演算子走査が右辺の初字まで読んでしまうため EV_RELGO で A6 を 1 戻す（算術経路は EV_OP が CHRGOT を使うため不要）。
9. **FETCH のプライミング規約との不整合（FOR の ?SN ERROR の真因）**: FETCH はハンドラ入口で既にトークンの次の文字まで A6/D0 を進めている。FORH/LETH/NEXTH の冒頭 CHRGET が二重に進め、PTRGET が '=' から名前走査を始めて TO まで食い進んでいた。3 箇所の CHRGET を削除。明示 `LET` も同病だった（未検証のまま潜んでいた）。
10. **PSH_FAC5 が自分の戻りアドレスの上にデータを積んでいた**: RTS がデータへ戻る。戻りアドレスを A0 に退避・復元して解決。
11. **FOR フレームと JSR 戻りアドレスの埋没**: 問題 10 と同族。FORH がフレームを積むとディスパッチ戻りアドレスがフレームの下に埋まり、RTS がフレームバイトへ飛んで幻の ?NF ERROR になった。「原典から外れた点」2 の退避方式で解決。
12. **run_m3.py の golden ゲート bug**: プログラム行の格納では CBM は READY. を出さないため ready_count が進まず、以降の全行が golden=None と誤判定されていた。プログラム行は出力安定待ちに変更（採取自体は全行成功していた）。

## M4 への引き継ぎ

- 目標は ASCIIART.BAS のバイト一致（golden: 2,025 バイト、25 行 × 79 字 + CRLF、sum16 25584、CRC32 0D6D8795）＝ Phase 1 受け入れ条件。
- M4 の実装対象: PRINT の完全な書式（',' のゾーン整形を原典準拠に）、IF、CHR$、文字列式・連結、文字列変数。FOR/NEXT と FP +−* は M3 で golden 一致済みなので、残る差は文字列と出力書式に絞られる。
- GOSUB/RETURN を入れる際は、FOR と同じ「戻りアドレス退避」の型が要る（JSR ディスパッチ前提の設計判断として確定）。
- 要判断-1（OUTSP $1D / $20）は M4 の PRINT 書式を詰める前に判断が要る。ASCIIART の golden は CBM 実測（$1D を含まない行末形式）なので、少なくとも行末の扱いは golden 側に合わせた比較設計にすること。
