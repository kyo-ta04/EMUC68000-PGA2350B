# M4 結果メモ — PRINT 完全化＋IF＋CHR$＋文字列式 → ASCIIART 合格判定

2026-11-18。対象: `msbasic68k.asm`（8,513 バイト、$0000–$2140）、検証: `run_m4.py`。
判定: **M4 PASS ＝ Phase 1 受け入れ条件を達成**（全チェック PASS、M1–M3 回帰 PASS、分岐先チェッカ 2 種とも 0 件不良）。

## ASCIIART 照合結果（Phase 1 合格判定）

- ASCIIART.BAS の 19 行をそのまま入力し RUN。RUN 直後に出力された絵 2,025 バイト（25 行 × 79 文字 ＋ CRLF）が **golden（CBM BASIC 2）とバイト完全一致**。
  - sum16 = **25584**（golden と一致）
  - CRC32 = **0D6D8795**（golden と一致）
  - 絵の直後に READY. へ戻ることも確認。
  - 食い違いは 1 バイトもなし（切り分け作業は不要だった）。
- **実行サイクル数**（emu の量子 100,000 サイクル単位で計測、±100k 程度の量子化誤差あり）:
  - セッション全体（起動＋19 行入力＋RUN＋終了行）: 1,212,600,000 サイクル
  - 入力のみ（RUN なし）: 1,000,000 サイクル
  - **RUN 区間 ≒ 1,211,600,000 サイクル ≒ 1MHz で約 1,211.6 秒（約 20.2 分）**
  - 参考: golden 採取時の 6502（CBM BASIC 2 / py65）実測は 491,353,778 サイクル（1MHz で約 491 秒）。単純比較では本移植は約 2.47 倍のサイクル数。Phase 1 の目的はバイト一致であり、速度は比較データとして記録するに留める（FAC メモリ常駐・バイト単位 FP 演算の忠実移植という設計判断の帰結）。

## 実装範囲

- **IF...THEN（IFH）**: 原典（m6502.asm 2464–2478）の構造そのまま。条件評価 → 終端が GOTO トークン（$89）なら THEN 省略形、さもなければ THEN トークン（$A7）を SYNCHR。偽（FACEXP=0）なら行末までスキップ（REMH 流用。IF は ':' 区切りの後続文も含め行全体を支配する、という原典 REMN の意味論）して次行へ。真なら、数字なら GOTOH へ（A6/D0 の priming 状態が GOTOH の入口と一致）、それ以外は FETCH 再入で文として実行（"THEN GOTO n" もこの経路で GOTOH にディスパッチされる）。ASCIIART の使用 2 形（`IF (式)>4 THEN GOTO 200`、`IF I>9 THEN I=I+7`）を含む全形を X セッションで検証。
- **CHR$（FE_CHR）**: 引数を評価 → CHKNUM → GETBYTE（0–255、外れたら ?IQ ERROR、原典 CONINT と同じ）。文字バイトは文字列領域から確保（FRETOP を下げる、原典 GETSPA 相当。GC は M5 なので枯渇時は ?OM ERROR）。ディスクリプタは文字列リテラルと同じ TEMPST スロットに長さ 1 ＋ ポインタで構築し、FAC+4 と VALTYP=$FF を設定。`PRINT CHR$(48);CHR$(49)` → `01` を確認。
- **文字列リテラル式**: M3 の FE_STR（TEMPST ディスクリプタ経路）がそのまま式として機能することを PRINT 経由で確認（追加実装なし）。
- **PRINT 完成**:
  - ',' ゾーン整形を原典のアルゴリズム＋ **REALIO=3 の定数**に合わせた: ゾーン幅 CLMWID=10、最終ゾーン開始 NCMPOS = ((LINLEN/CLMWID)−1)*CLMWID = ((40/10)−1)*10 = **30**。カラム 30 以上での ',' は CRLF を出して次の項目へ（原典 COMPRT）。M3 の簡易版（閾値 70）から変更。
  - 数値末尾バイトは **NUMSPC EQU $20** として 1 バイト定数化（要判断-1 は未決のまま。CBM の $1D に切り替える場合はこの 1 箇所だけ。ゾーン埋め・TAB/SPC の空白は従来通り実スペース）。
  - 引数なし PRINT（改行のみ）は M2/M3 時点で動作済み、ASCIIART 220 行で実証。

## 踏んだ問題

1. **M3 由来の潜在バグ: ゾーン／TAB／SPC の空白ループが 1 個少なく印字**。PRZONE と PRTAB の両ループが「先にデクリメントしてから印字」する形で、要求数 −1 個しかスペースを出していなかった（M3 では ',' も TAB/SPC も個数検証がなかったため潜伏）。M4 のゾーン検証（`PRINT 1,2` が 1 桁短い）で発覚。両ループを「印字してから数え下げる」形に直し、SPC(3)／TAB(5)／TAB(6) の回帰チェックを run_m4.py に追加して固定。
2. **run_m4.py 側の判定ミス（実装は正常）**: IF..GOTO の成否を生トランスクリプトの部分文字列で判定したら、入力エコー中のプログラム行自体（`20 PRINT "BAD"`）に反応して FAIL になった。RUN の応答ペイロードを出現順に取り出して判定する方式に修正。
3. **テスト期待値の誤り（実装は正常）**: `CHR$(48+2)` は '0' でなく '2'（48+2=50）。期待値を疑う前に検算し、テストを `CHR$(48)` に直した。

## 原典から外れた点

1. **CHR$ の文字列確保に GC がない**。原典 GETSPA は不足時に GARBAG を回すが、本移植は ?OM ERROR で落とす（GC は M5）。ディスクリプタも TEMPST 単一スロット（リテラルと共用）で、同時に生きる文字列テンポラリは 1 つまで。連結（下記）が入る M5 で原典のテンポラリスタックに戻す。
2. **文字列連結 '+' は未実装（M5）**。`PRINT "A"+"B"` は左リテラルを印字した後 ?SN ERROR になる（現状の文書化された挙動として run_m4.py に固定）。文字列変数・文字列比較（RELOPS の文字列経路）も M5。
3. **ゾーン閾値と端末モデルの不整合（M5 で統一判断）**: ',' の NCMPOS は原典 REALIO=3 の 40 桁画面（LINLEN=40）から 30 にしたが、本移植の他の端末モデルは 80 桁ストリーム前提（PRWIDTH の折り返し判定 80、OUTDO に折り返しなし）。ACIA ストリームには画面幅の実体がないための暫定混在で、ASCIIART（',' も数値 PRINT も使わない）には無影響。M5 で端末モデルをどちらかに統一する際に再判断。
4. **GOSUB/RETURN は未実装（M5）**。ASCIIART は使わないため入れていない。入れる際は FOR と同じ「戻りアドレスの ZP 退避」方式を使う（M3 引き継ぎ通り）。
5. **IF の偽スキップは REMH 流用**（引用符を解釈しない行末スキップ）。トークン化済みテキストに NUL は現れないため、引用符内の ':' も正しく行末まで読み飛ばされる（IF の意味論としては原典 REMN と等価な結果になる）。

## M5 への引き継ぎ

- 文字列の本格化: 文字列変数、連結（CAT）、文字列比較、テンポラリディスクリプタのスタック化、GETSPA＋GARBAG（GC）。CHR$ の確保経路はそのまま GETSPA に接続できる形にしてある。
- GOSUB/RETURN（戻りアドレス退避方式）、配列、INPUT/READ/DATA 実行時読み、残りの関数（SQR/LOG/EXP/三角関数/RND、STR$/VAL/ASC/LEN/LEFT$/RIGHT$/MID$）、^（FPWRT）。
- 端末モデルの統一判断（上記 3）と、要判断-1（NUMSPC $20/$1D、Kyo の判断待ち）。
- Phase 1 の残作業は M5 の faithful 完成のみ。受け入れ条件（ASCIIART バイト一致）は本 M4 で達成済み。
