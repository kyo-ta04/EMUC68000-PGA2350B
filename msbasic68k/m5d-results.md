# M5d 結果メモ ― 数学パック残り＋文字列関数＋PEEK/POKE/WAIT（Phase 1 完成）

対象: `msbasic68k.asm`（最終イメージ **14,862 バイト**）、検証ハーネス `run_m5d.py`。
期待値の正は 6502 golden（py65 + cbmbasic2.bin）。数値の末尾バイトは NUMSPC=$20（port）/
$1D（golden）を正規化して照合。端末幅 80 桁は M5a 確定のまま不変。

## 実装範囲

- **累乗 ^（FPWRT）**: M3 以来のスタブを本実装に置換。原典の手順通り
  （y=0 は EXP へ落ちて 1、x=0 は負の y でも 0、負の底は INT 一致時のみ符号処理、
  それ以外は LOG 経由で ?IQ）。
- **数学関数**: SQR（FPWR への尾呼び出し）、LOG、EXP、SIN、COS、TAN、ATN。
  原典の多項式定数は golden ROM のバイト列と全数照合済み（下記「踏んだ問題」5）。
- **RND**: 原典生成器（RNDX × RMULZC + RADDZC ＋ 仮数バイト反転）を移植。
  初期シードは原典 cold start の 1 バイト欠けコピーを再現（$80 $4F $C7 $52 $00）。
- **文字列関数**: STR$、VAL、ASC、LEN、LEFT$、RIGHT$、MID$（原典のエラー挙動込み）。
- **PEEK/POKE/WAIT**: 論理アドレス定義は下記。WAIT は条件成立済みなら即戻る。
- **型検査**: 数値関数は原典どおり引数の型を検査（SGN/INT/ABS/SQR/RND/LOG/EXP/
  COS/SIN/TAN/ATN は評価後に CHKNUM する FE_UFN 経路。PEEK/FRE/POS は原典同様無検査）。
  GETBYTE に CONINT 相当の CHKNUM＋符号検査を追加。

## PEEK/POKE/WAIT のアドレス定義（本移植の定義）

- 引数は原典 GETADR 通り（負数と 131072 以上は ?IQ、値は mod 65536）。
- 物理アドレス = **ZPBASE（$010000）+ 論理アドレス**。論理 0 = 仮想ゼロページ、
  論理 $0310〜$FFFF はスクラッチ RAM。POKE→PEEK ラウンドトリップ成立。
- ACIA はこの写像では届かない（Phase 1 の範囲外として確定）。

## 照合結果（run_m5d.py）

**116/118 checks PASS**。内訳:

- RND 系列（起動直後の系列、RND(0) 後、負シード再現性）: 全て golden バイト一致。
- ^ バッテリー: 2^10、2^0.5、(-2)^3、0^0、0^-1=0、エラーケース: 一致（2^31 のみ下記相違）。
- SQR/LOG/EXP バッテリー: 全て一致（EXP(±50)、EXP(±80)、SQR(12345) 含む）。
- 三角関数バッテリー: SIN/COS/TAN/ATN の代表値（0、正負、大値 123456、1E10）:
  COS(3.14159265) のみ下記相違、他は全て一致。SIN(0.7)^2+COS(0.7)^2 = 1 も一致。
- 文字列関数: 代表ケース＋境界（空文字列、範囲外、?IQ/?TM の出所）全て一致。
- PEEK/POKE/WAIT: ラウンドトリップ、WAIT 即戻り（mask のみ／mask+xor）、
  アドレスエラー系: 全て一致。
- 格納プログラム（SIN/LEFT$/MID$/VAL/POKE/PEEK/WAIT 使用）＋プログラム文脈の
  エラー表示（?IQ ERROR IN 10）: 一致。
- **回帰 run_m1.py〜run_m5c.py: 全て PASS（ASCIIART バイト一致を含む）**。
- 分岐先チェッカ 2 種: 0 bad。

## 残った相違（2 件、いずれも表示最終桁の 1 ulp）

### 1. `PRINT 10^38; 2^31` ― byte 17 で初出
golden `2.14748365E+09` / port `2.14748366E+09`。
切り分け: EXP 単体（`EXP(21.4875626)`）は両機とも -3（2^31-2147483648）で一致し、
LOG(2) の 32 ビット仮数も一致する。拡大プローブ `(LOG(2)-.693147181)*1E9` で
golden=0 / port=0.232830644（=2^-32）となり、**相違は LOG(2) の拡張バイト
（FACOV）のみ**（port は $B0、golden は $80 未満＝後段の MOVAF 丸めで繰り上がらない）
と特定した。port の LOG(2) チェーンは全段（FADD/FDIV/FSUB/POLYX/FINLOG/最終 FMULT）
をデバッガ実測＋厳密有理数シミュレーションで照合し、モデルと完全一致することを
確認済み。原典側の拡張バイトは 6502 のシフト機構（ROLSHF/MLTPLY のビット単位
切り捨て詳細）に依存し、py65 ハーネスでは途中値を観測できず、最終的な 1 バイトの
出所までは特定できなかった。2^30 でも同種の最終桁差が出る（バッテリー外で確認）。
実害は「真値が表示丸め境界にある場合に最終桁が 1 違う」ことに限られる。

### 2. `PRINT SIN(3.14159265); COS(3.14159265); ...` ― byte 16 で初出
golden `-.999999999` / port `-1`。
切り分け: 引数の和（3.14159265+π/2）は両機で 40 ビット精度まで一致
（差分プローブ 0）。SIN(4.71238898) 単体では golden が -1+4.65661287E-10、
port がちょうど -1 を返し、SIN の象限折り畳み後の POLYX 評価の拡張バイト差が
境界を跨いだもの。なお COS(3.14159) は両機とも -1 で一致する（golden 側も
境界で割れる入力）。1. と同根（多項式チェーンの拡張バイト）と判断した。

## 原典から外れた点（意図的・観測可能なもの）

- **SQR("A")**: golden は ?IQ（ディスクリプタを数値と誤読して LOG で落ちる）、
  port は FE_UFN の型検査で ?TM。型混同入力に対する相違として明記する。
- **USR**: golden は ?IQ（ベクタ先が FCERR）、port はスタブの ?SN。
- **TI/TI$**: golden ハーネスでは TI=0、TI$="000000" を返す（タイマ読み）。
  port にはタイマが無く、TI は通常変数（0）、TI$ は通常文字列変数（空）として扱う。
- **RND(0)**: 実機 CBM ではタイマレジスタを読む。golden ハーネスでは該当セルが
  0 のため「FAC:=0、RNDX:=0」に潰れ、port も同じ挙動に合わせてある
  （エントロピー源は持たない）。
- **POS**: golden ハーネスは桁位置を持たないため常時 0。port は仕様通り実桁を
  返す（"ABC" の後で 3）。仕様照合で PASS とした。

## 踏んだ問題（発見順、すべて修正済み ※印を除く）

1. **ZP 絶対 EQU への PC 相対 LEA**: TEMPF1/2/3・RNDX は絶対 EQU なのに
   `LEA label(PC)` と書いた箇所（14 か所）が黙って化け、ST_FAC が暴走アドレスに
   書いてハング。`MOVEA.L #...` に統一。教訓: イメージ内ラベルは (PC)、ZP EQU は絶対。
2. **INTEGR バイト欠落**: 原典 INT は QINT 直後の低バイトを専用バイト INTEGR に
   保存し EXP/FPWRT が読む。port の INTFN が保存しておらず、変換後の FAC+4（=0）を
   読んで EXP のスケールが常に喪失（EXP(2) が e²/4 になる等）。ZP $32E に INTEGR を追加。
3. **MOVE.W が N フラグを壊す**: SIN/ATN の符号退避（PUSH）直後の分岐が 6502 の
   PHA と違いゴミで決まっていた。PUSH 後に明示 `TST.B FACSIGN` を追加。
4. **TAN/COSC のスタック順**: 原典 COSC は戻りアドレスの上に符号バイトが乗る
   構造。port の「PUSH して BSR」では順序が逆になり ?NF に暴走。
   トランポリン（PUSH して BRA）で再現。
5. **SINCON 定数転記ミス**: 原典の 8 進 065 を $65 と写し SIN/COS 全般が微妙に
   ずれていた（$35 が正）。以降、全定数を golden ROM のバイト列と照合した。
   なお原典ソースの 10 進コメントはバイト列と合わない箇所があり、ROM が正。
6. **FACOV のライフサイクル**: 原典のコピー/ストア原語（MOVMF/MOVAF/MOVEF/MOVFA）は
   全て末尾で FACOV:=0 にする。port の ST_FAC/CP_F2A(R) が残存させており、
   RND(0) の次値・TAN(1)・LOG(10) が 1 ulp ずれていた。原典通りにゼロ化。
7. **WAIT の EOR 誤アセンブル**: `EOR.B EORMSK,D0`（メモリ源）を asm68k-py が
   `EOR.B D0,D0` に化かし WAIT が無限ループ。レジスタ経由に変更（既存慣行）。
8. **エラー経路の TEMPPT 未リセット**: 原典は全エラーが TYPERR→STKINI で
   文字列テンプリを全解放する。port の ERROR は行っておらず、テンプリを抱えた
   エラー（SIN("A") の ?TM 等）を 3 回出すと以降の文字列演算が全て ?ST になった。
   ERROR に TEMPPT リセットと SUBFLG クリアを追加。
9. **FMULT の ARG=0 早期出口欠落**: 原典 MULDIV は ARGEXP=0 で ZEROFC。
   port は FAC=0 しか見ておらず、LD_ARG が立てた隠しビットのせいで
   「FAC × 2^-129 のゴミ」を返し、SIN(0)/TAN(0) が 9.23231105E-39 になった
   （POLYX の TEMPF2=0 経由）。`TST.B ARG; BEQ ZERO_FAC` を追加。
10. **NEGOP のゼロ扱い**: 原典 NEGOP は単一で FACEXP=0 をテストする。
    port の評価器 NEGOP は無条件反転で PRINT -0 が "-0"、VAL("-0") が -0 になった。
    テストを追加（NEGOP_F と同一挙動に）。
11. **FCOMP 最終バイトの bias 借り潰し**: P4-FAC4 の後に SUBQ したため借りが
    消え、1 ulp 差を誤判定。FOUT のスケーリングが回り過ぎて 99.9999999 が
    ":0" と表示された。原典の SBC 連鎖と等価なワード演算に書き換え。
12. **EXP の分数減算で拡張バイト相殺**: 原典の拡張バイトは FAC 側だけの共有
    1 バイトで、ARG のフィールドは [仮数][0]。port の EXP_FN が ARGEXT にも
    OLDOV を入れ、減算で拡張が相殺され f の最下位バイトが欠落（EXP(50) 等が
    2^-27 級でずれ、2^31・SQR(12345) にも波及）。ARGEXT:=0 に修正。
※ **FADD の sticky 補正**: 原典 FADDT に sticky は無いように読めたため除去を
    試したが、port の FADD は sticky 前提で調整された系であり全面崩壊したため
    復元した（除去版は COS が 11.76…、2^31 が ?OV）。上記「残った相違」2 件は
    この sticky を含む port のシフト/切り捨て詳細と原典の差に帰着すると判断し、
    これ以上の単独変更は回帰リスクが大きいため見送った。

## Phase 1 完成時点の残存スタブ・既知の制限

### 残存スタブ（未実装）

### 既知の制限（M5a〜M5c からの引き継ぎ含む）
- STOP を FOR/GOSUB の内側で実行すると CONT 文脈を失う。

- 文字列ディスクリプタは奇数アドレスでのロングアクセスを含む
  （sim は許容するが実機 68K ではアドレスエラーになるため、実機フェーズで
  ディスクリプタ形式の再設計が必要）。
- FN 定義テーブル FNTABV は sim 専用アドレス（$018000）に置いたまま。
  実機メモリマップ決定時に移設する。
- 本メモ「残った相違」2 件（表示最終桁 1 ulp、計算チェーン経由のみ）。
