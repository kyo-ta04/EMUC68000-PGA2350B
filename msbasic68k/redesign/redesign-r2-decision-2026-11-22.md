# R2 入口決定（2026-11-22、Kyo）

出典：サイドチャット「MS-BASIC 68K R2 検討」2026-11-22 16:50 JST。

## 決定

1. **D1–D10 は推奨案通りで承認**（`redesign-r0-design.md` §3）。
   - D1 整数リテラルは int32 に収まれば整数型、D2 +−* は両辺整数なら整数演算・/ は常に FP・\ と MOD 採用、D3 オーバーフローは黙って FP 昇格、D4 整数 FOR 許可（原典 ?SN の意図的逸脱）、D5 代入変換は現行鎖維持、D6 PEEK/DEEK/LEEK は整数を返す、D7 % 配列の実演算化、D8 USR 型タグ受け渡し（現行規約維持）、D9 整数 PRINT、D10 READ/DATA は D1/D5 準拠。
2. **「快適」の優先順位を変更**：動くものを手に入れる >> 快適。
   - Kyo の言葉：Unix の流儀。まず動く実装を手に入れることが先で、速度はその後。
   - したがって R2 受け入れで速度は**計測・記録項目**であり、合否ゲートではない。52.5e9（EhBASIC の 1/3）、EhBASIC 同等〜2倍、といった帯は R2 の go/no-go 基準から外す。
   - 速度の本命レバーは将来段に残す：R3 中間コード（バイトコード VM）、R4 ASM.BAS バックエンドのネイティブコンパイラ。当初計画通り視野に入っている前提で、R2 で無理に稼ぎに行かない。

## R2 受け入れ条件（改訂案）

- 既存スイートの振る舞い一致（ゴールデン維持、D1–D10 で意図的に変わる箇所は専用チェックで明示）
- ASM.BAS 移植版が R2 上で test4 → フルランの順に**バイト一致**で完走すること（slot5 13,788 B / sum 41893、SYMBOLS 1095）
- サイクル数は実測して記録する（合否には使わない）。フルラン前に計装版で周回数と ETA を実測ベースで出す（2026-11-22 の進捗表示ルール）

## R2 マイルストーン案（小さく検証可能に、予測先行）

- M1 型の土台：型タグ伝播の置き場、D1 リテラル、D9 PRINT、D5 代入。演算子はまだ変えない
- M2 整数演算子：+ − * と混合比較、D3 昇格
- M3 \ / MOD と D4 整数 FOR
- M4 D6 関数、D7 配列、D10 READ/DATA、D8 USR
- M5 レジスタ FAC（D4/D5 案）＋数値パック原生化（優先順位は M9 と R0-2 実測で）
- M6 ASM.BAS 再ベンチ（test4 → フルラン、バイト一致が受け入れ）

各 M でスイート全通過＋専用チェック追加を門とする。
