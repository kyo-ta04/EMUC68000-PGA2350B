## 変更内容（ファイル／ラベル別）

### parts/20-equates.asm
- 新 ZP スロット：FACINT（$1E8、4B）、ARGINT（$1EC、4B、M2 予約）、FACTYP（$1F0、1B：0=FP／1=INT）、ARGTYP（$1F1、M2 予約）、FININT（$1F4、4B）、FINFLG（$1F8、1B）。いずれも ZPSIZE（$332）のクリア範囲内。
- **INTTAG = $49（'I'）**：通常変数／配列要素の値フィールド +5 バイトに置く型タグ（下記 D5）。
- LCACHE コメントを 128×32B に更新。

### parts/60-core-b.asm
- **二重表現の土台**：FACTYP=INT のとき FACINT が厳密な int32、FAC にはその FP 変換（厳密）も常駐。VALTYP には一切手を入れていない（二値のまま）。
- `SFLOAT32`（新規）：D0.L の符号付き int32 → FACINT/FACTYP=1 ＋ FP シャドウ。-2147483648 の否定が $80000000 = 大きさ 2147483648 として正しく読める形。0 は NORMALIZE→ZERO_FAC 経由で FP 0 に劣化（観測上同一、記録済みの既知事項）。
- `FAC32I`（新規）：LD_FAC 直後の FAC が int32 範囲の厳密な整数なら FACINT/FACTYP を復元、でなければ FACTYP=0。FAC は不変。タグの**検証器**として働く（タグはヒントに過ぎず、値は常に FP シャドウから再導出するので、タグバイトを保守しない経路（FOR/NEXT、FN 引数設置）が古いタグを残しても誤値にはならない）。
- クリア規律のチョークポイント：`ZERO_FAC`、`FLOAT_BYTE`（SGN／関係演算の結果もここを通る）、`GIVAYF` に FACTYP クリアを追加。`PERFORM2` は演算子実行直後にクリア（M1 では演算結果は常に FP。M2 で整数演算子が保持する側に回る）。`ST_FAC_TAG`（新規）：ST_FAC ＋ 値フィールド +5 への INTTAG 書き／消し。
- `FIN`／`FIN_HIT`／`LC_CLEAR`：キャッシュエントリ **32B×128**（同 4KB 枠、ハッシュは & $7F、<<5）。レイアウト：+0 テキストアドレス、+4 終端アドレス、+8..+12 FAC（exp＋仮数）、+13 FACOV、+14 終了 D0、+15 FACTYP、+16 FACINT、+20..+31 pad。無効化規則（SCRATCH／STORE で消去、RUN／STOP／CONT で保持）と VAL の終了 D0 厳密性は従来通り。
- `FIN_PARSE`／`FIN_IDIG`（新規）：FP 蓄積と並行して int32 蓄積。'.'／'E'／int32 溢れ（214748364 境界で判定）で候補落ちし、その場合は従来通りの FP リテラルとして終わる。候補のまま終われば FACTYP=INT、FACINT=値、FAC=FP シャドウ。
- `FOUT_INT`（新規、D9）：FACINT → FBUFF。符号文字（正は空白、負は '-'）＋ DIV10 による10進数字。FOUT と同じバイト形式。
- `FRM_VARIABLE`：% ロードは 4 バイト読み → `SFLOAT32`（INT としてロード）。通常変数は LD_FAC 後、VARPNT が VARTAB 以上（＝C_ZERO 定数でない）かつ +5 が INTTAG のときだけ `FAC32I` で INT 復元。文字列ロードは FACTYP クリア。
- `PTRGET_ARR`／`ARR_ES`：% 配列の要素サイズ **2→4**。ELMSZ を使う他の全経路（ブロック構築、インデックス計算、GC のブロック歩行）が同じ定数を参照するので不整合なし。添字上限 32,767 は不変。

### parts/62-core-b2.asm
- `FE_UF`／`FE_UFN`：関数実行直後に FACTYP クリア（チョークポイント）。副作用として VAL("123") の INT 化は M4（D10 の残り）に送った（現在は FP 123、表示は同一）。

### parts/64-core-b3.asm
- `PUTNEW`：FACTYP クリア（全ての文字列生成のチョークポイント。CAT もここを通る）。
- `LETCORE`：FP ターゲットは `ST_FAC_TAG` 経由に。% ターゲットは新設 `STO_INT32` へ。
- `STO_INT32`（新規、D5）：INT 結果は FACINT を直接 4 バイト格納。FP 結果は従来チェーン（ROUND_FAC → 床変換）を int32 範囲チェック付きで：丸め後に範囲外なら ?IQ（従来 AYINT と同じエラー）。指数 160 帯は正は常時範囲外、負はちょうど -2147483648 のみ可。床の意味論は継承（実測：2.5→2、3.5→3、-2.5→-3）。
- `INPASSIGN_NUM`：LET と同じ2ストアに統一（FP は ST_FAC_TAG、% は STO_INT32）。READ/DATA の数値項目は INPFIN の FIN 結果が D1 型を持つので、D10 の代入側はこの共有で成立。
- `INPFIN`：負号付き INT は FACINT も否定（二重表現の整合、DATA -123 等）。

### parts/4A-core-a6.asm
- `PRITEM`（D9）：VALTYP 数値かつ FACTYP=INT なら `FOUT_INT`、でなければ従来 `FOUT`。PRWIDTH／FBUFF 印字／NUMSPC の後段は共通。

### parts/70-ext1.asm
- `UFLOAT`：FACTYP クリア追加（FP 生成側）。
- `FE_HEX`（D1）：$7FFFFFFF 以下は `SFLOAT32` で INT 結果に（FAC 値は従来と同一）。超える場合は従来通り UFLOAT の符号なし FP。終了文字 D0 はスタックに退避して契約を維持。

### run_rd.py
- 新規チェック **17件**（SESSION の R2-M1 節）：INT 境界表示、FP のまま残る 4294967295／&H80000000、通常変数の INT 往復とタグ消去、% の 70000／±境界、FP→% の床（2.5→2、-2.5→-3）、範囲外 ?IQ ×2、% 配列の大きな値と要素独立性。
- **従来チェックの変更は SESSION2 の1グループのみ**（下記「意図的な振る舞い変更」2）。

## 意図的な振る舞い変更（D1／D5／D9 の帰結）

1. **大きな整数の表示**：INT として保持される値は E 記法でなく整数のまま表示される。例：`PRINT 2147483647` は従来 ` 2.14748365E+09 ` → 新 ` 2147483647 `、`A=2000000000: PRINT A` は ` 2E+09 ` → ` 2000000000 `。演算を経た値（例 `PRINT 0-2147483648`）は FP のまま従来表示。これは D9 そのもの。
2. **% 配列の容量**：要素 4 バイト化で、R1 の A1 受け入れ配列 A%(200,200)（40401 要素）が 161,618 バイトとなり 129,024 バイトの空間に収まらず ?OM になる。SESSION2 の当該グループは寸法を A%(200,100)（20301 要素、81,212 バイト）に変更して「64KB 超の単一ブロック」という検証目的を維持した。期待出力の値そのもの（12345 等）は不変。
3. **% 代入の範囲**：従来 ?IQ だった 70000 や -2147483648 が入るようになった（D5 の int32 化）。逆に int32 を超える FP→% は従来通り ?IQ。-32768 の原典癖（?IQ）は int32 化で消滅（範囲内になったため）。

## 先送り・既知事項

- **演算子は未変更**（M2）：PERFORM2 で FACTYP を落とすので、`100000*3` 等は FP 経路のまま正しい値を返す。ARGINT／ARGTYP は equates の予約のみ。
- **VAL の INT 化**は FE_UF の一律クリアで FP に倒れる（M4／D10 で再訪）。
- **INT 0 の劣化**：SFLOAT32 の 0 は FP 0 になる（PRINT・代入とも観測同一）。
- **FOR % は ?SN のまま**（D4 は M3）。プローブで維持を確認。
- D6（PEEK／DEEK／LEEK の INT 返却、SGN／ABS／INT の型規則）は M4。現状 DEEK 等は FP 返却のまま（値は同一）。
