# M5f 結果メモ — Phase 1.5 Step 2: 着陸ゾーン $30000 の実機マップ版（2026-11-19）

Phase 1.5（実機 readiness）の Step 2。実機（EMUC68000-PGA2350B、
EhBASIC 稼働中）の着陸ゾーン $30000–$3FFFF（64KB）にロードし、
EhBASIC の `CALL $30000` で起動できるビルド変種を作り、sim で
検証した。実機での実行確認は Step 3（本メモの手順と予測値を使う）。

**結論: sim 検証 28/28 PASS（通常 emu／emu_strict 両方）。**
実機版イメージ **15,234 バイト**、BSD sum **43082**、
BYTES FREE **40,960**。

## ビルド方式（フォークなし）

- `build_hw.py` が `msbasic68k.asm` を読み、設定ブロック
  （ORG と関連 EQU）とリセットベクタ部だけを書き換えたコピー
  `msbasic68k-hw.asm` を生成して asm68k-py でアセンブルする。
  本体側の修正はそのまま実機版に流れる。各置換アンカーは
  「ちょうど 1 回出現」を assert し、レイアウト不変条件
  （後述）も assert する。
- ついでに DATA 埋め込みローダ `msbasic68k-hw-loader.bas`
  （55,042 バイト）も生成する（手順は後述）。

## 配置マップ（全てゾーン $30000–$3FFFF の内側、全ベース偶数）

| 領域 | アドレス | 備考 |
|---|---|---|
| コード | $30000–$33B81（15,234 B） | 先頭は HWENTRY（ベクタではない）。ZPBASE まで 1,150 B の余白 |
| ZP ミラー | $34000（$330 使用） | sim 版 $10000 から移設 |
| FN 定義表 | $34800（最大 $300） | 64 レコード × 12 B |
| TXTTAB | $35000 | プログラム／変数／文字列がここから上下に伸びる |
| MEMSIZ | $3F000 | 文字列空間の上限 |
| スタックトップ | $40000（初期 SSP） | ゾーン末尾の 1 つ先。MEMSIZ との $1000 の間隔は sim 版の関係を踏襲 |

- **BYTES FREE = 40,960**（MEMSIZ $3F000 − TXTTAB $35000）。
  バナー表示と FRE(0) で実測確認（下記）。
- **入口 HWENTRY**: `MOVE.W #$2700,SR`（スーパーバイザ、全割り込み
  マスク。実機はポーリング I/O なので安全側）→ `LEA STACKTOP,A7`
  （自前スタックをゾーン末尾に）→ `BRA INIT`（通常のコールド
  スタートへ）。呼び出し側の戻りアドレスは捨てる前提で、
  **REPL は戻らない。終了は実機リセット**。
- **ACIA は $80E000/$80E001 のまま**（sim と実機で同一、確認済み）。
- PEEK/POKE の論理アドレスは GETADR が ZPBASE 基点で変換する
  ため、実機版では論理 0 = 物理 $34000 に自動で追随する。

## sim 検証（run_hw.py）

emu は $0 のベクタから起動するため、ベクタスタブ
（SSP=$40000、PC=$30000）＋実機版バイナリを $30000 に置いた
**合成イメージ**（211,842 バイト）で起動した。これは実機で
CALL $30000 が入る位置・状態と等価。

通常 emu と emu_strict の両方で同一に実施し、全て PASS:

- バナー `### COMMODORE BASIC ###` → `40960 BYTES FREE` →
  `READY.` の順で出現
- `PRINT 2+3*4` → ` 14 `、`PRINT 1/3` → ` .333333333 `
- 文字列変数＋連結 `A$="FOO":B$="BAR":PRINT A$+B$+"!"` → `FOOBAR!`
- GOSUB/RETURN の小プログラム → `SUB` / `BACK`
- **GC ストレス**: 文字列空間 約 40KB に対し 2,000 回の連結で
  約 280KB のゴミを生成 → `SURVIVED`、最終文字列も正しい
  （GARBAG が実機マップでも動作）
- 蓄積 `A$=A$+"AB"` × 50 → `AB` × 50
- **ASCIIART.BAS: 絵が golden とバイト完全一致**
  （2,025 バイト、sum16 25584、CRC32 0D6D8795）、直後に READY 復帰
- 分岐先チェッカ 2 種とも 0 bad（HW リスティング＋合成イメージ）

サイクル数（emu 実測、±100k 量子化）:

- スモークセッション全体（入力＋上記テスト一式）: 45,300,000
- ASCIIART セッション全体: 1,322,300,000（Step 1 のアライン版
  sim 測定 1.3222e9 と一致。配置換えによる速度変化なし）

## 実機ロード手順（Step 3 用、前例ベース）

前例: 着陸ゾーン決定（landing-zone-experiment.md、実機全段階
PASS）と、DATA 埋め込み＋POKE＋検証ローダのパターン
（step3/build_puncher_v3.py、usr/build_sumusr.py）。新方式は
導入していない。

1. **予約（コールドスタートのたび）**: EhBASIC 直接モードで
   `LOKE $844A,$30000` → `CLEAR`。EhBASIC の文字列空間が
   ゾーンに降りてこないようにする。現在の実機ブート
   （260628 Bytes free 表示）では必須。省略すると MS-BASIC の
   コード／作業域を EhBASIC 側が踏む。
2. **ローダ投入**: `msbasic68k-hw-loader.bas`（55,042 バイト）を
   EhBASIC コンソールへ送る（Tera Term の送信ディレイ付き
   ペースト、または step3/send_throttled.py のドリップ送信）。
   そのまま `RUN`。
   - ローダは DATA から 15,234 バイトを $30000 へ POKE し、
     全バイトを PEEK で照合しながら BSD sum を畳む。
   - 成功表示: `LOAD OK - 15234 BYTES AT $30000, SUM 43082`
   - 失敗時はミスマッチ件数と実測 sum を表示する。その場合は
     CALL に進まないこと。
3. **起動**: 直接モードで `CALL $30000`。
   MS-BASIC のバナーが出れば H1 通過。
4. **スモーク（Step 3 の H2）**: READY プロンプトで run_hw.py の
   スモークと同じ入力を手で打つ（予測値は下表）。
5. **ASCIIART（Step 3 の H3）**: 19 行を入力して `RUN`。
6. **終了**: MS-BASIC は EhBASIC に戻らない。実機リセットで
   EhBASIC に復帰する（PSRAM テープは電源断で消える仕様に注意。
   必要なテープは先に PC へ読み戻しておくこと）。

テープ経由のバイナリ転送にしなかった理由: 既存の Puncher
（RCVUSR）は CR を読み飛ばすテキスト前提で、生バイナリは
uuencode が要るが、機上 uud は Phase 3 の未実装項目。DATA
埋め込みは遅いが実績のある経路をそのまま使った。

## Step 3 への引き継ぎ（予測値）

sim 実測に基づく、実機で照合すべき予測:

| 項目 | 予測 |
|---|---|
| ローダ照合 | `LOAD OK - 15234 BYTES AT $30000, SUM 43082` |
| バナー | `### COMMODORE BASIC ###` / ` 40960 BYTES FREE` / `READY.` |
| `PRINT 2+3*4` | ` 14 ` |
| `PRINT 1/3` | ` .333333333 ` |
| `PRINT FRE(0)`（起動直後） | ` -24580 `（40,956 を符号付き 16 ビットで読んだ値。sim 合成イメージで実測済み） |
| 文字列連結 | `FOOBAR!` |
| GOSUB 小プログラム | `SUB` の次に `BACK` |
| GC ストレス | `SURVIVED`＋数字 50 文字（計算時間は 6MHz で約 8 秒弱、入力時間を除く） |
| ASCIIART | 絵は golden と同一（25 行 × 79 文字）。所要 **約 220 秒（3 分 40 秒）@6MHz**／約 22 分 @1MHz |

注意点:

- コードの余白は ZPBASE まで 1,150 バイト。本体が育つと
  build_hw.py の assert が落ちるので、その時は ZP 以降を
  後ろへずらす再配置が要る（BYTES FREE が減る）。
- 監査（Step 1）のカバレッジは「スイートが踏んだ経路」まで。
  実機スモークで文字列・GC・配列・FN を一通り触るのは、
  未踏経路の奇数アクセスが残っていないかの最終確認も兼ねる。
  アドレスエラーが起きると実機では無言でハングしうるので、
  H2 は小さい順に段階を踏むこと。
- 実機の ACIA 送信は sim と違い実時間。ASCIIART の 2,025 バイト
  出力は 6MHz の計算約 220 秒に対して無視できる規模。
