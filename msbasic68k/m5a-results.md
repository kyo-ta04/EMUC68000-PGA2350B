# M5a 結果メモ — 文字列の本格化＋GOSUB/RETURN＋GC（端末幅 80 桁統一を含む）

2026-11-19。イメージ 9,671 バイト（M4 の 8,513 から +1,158）、ソース 3,520 行。
検証は `run_m5a.py` で **65/65 PASS**（M5a セッション全体で約 65.6M サイクル、
うち大半が GC ストレス 2 本）。分岐チェッカ 2 種とも 0 件。回帰 run_m1.py〜
run_m4.py は全て exit 0（run_m4.py の期待値 2 件だけ M5a 仕様に更新、後述）。

## 実装範囲

1. **GOSUB/RETURN**: M3 の FOR と同じ設計型。22 バイトフレーム（戻り
   TXTPTR＝終端文字 ':' か NUL の位置、CURLIN+OLDLIN、CURLINP、FORSP、
   前任 GOSUBSP、印字 $8D00）を CPU スタックに積み GOSUBSP で連結管理。
   RETURN はフレームを復元し、サブルーチン内で開いた FOR フレームごと
   スタックを巻き戻して EXEC に戻る。ネスト対応。相手のない RETURN は
   ?RG ERROR。出口条件の基本形・2 重ネストとも golden 一致。
   追加で確認: FOR の内側から GOSUB（ループ変数がサブルーチンで見える）、
   サブルーチン内の FOR を RETURN で放棄（FORSP がフレームから復元される）。
2. **文字列変数**: スカラー文字列変数。LET（暗黙含む）の代入・再代入は
   原典 PUTSTR の所有権規則そのまま（下記）。
3. **文字列連結 CAT**: '+' の文字列経路。テンポラリディスクリプタは原典の
   テンポラリスタック方式に戻した（TMPDSC に 3 個×5 バイト、TEMPPT/LASTPT、
   PUTNEW/FRETMP/FRETMS、NUMTMP=3）。M4 の単一スロット制約は解消。
   合計長 >255 は ?LS ERROR（STRING TOO LONG）。
4. **文字列比較**: STRCMP。両辺のテンポラリを原典順（右を FREFAC、左を
   FRETMP）に解放し、短い方の長さまでバイト比較、同値なら長さで決定。
   結果は数値経路と同じ符号化（1/0/$FF）とマスク対応（REL_T 相当）を通す。
   IF の =、<>、<、>、<=、>= すべて golden 一致。PRINT 式中でも -1/0 を確認。
5. **GETSPA＋GARBAG（GC）**: 原典アルゴリズムを移植。FRETOP を MEMSIZ から
   建て直し、「FRETOP 未満で最も高いデータ位置にある生存文字列」を繰り返し
   最上部へ詰める。走査対象はテンポラリスタックと単純変数（配列は M5b）。
   GETSPA は不足時に GC を 1 回だけ回して再試行し、それでも不足なら
   ?OM ERROR。**FRE(0)** も実装（文字列引数なら FREFAC で解放→GC→
   FRETOP−STREND を符号付きワードで float。原典の注意書き通り 32767 超は
   負になる。本マップでは初期状態で 61,436 バイト→ **-4100**、実測一致。
   FRE("X") も同じ値＝テンポラリ解放と FRETOP の pop が効いている証拠）。
6. **端末幅 80 桁統一**（Kyo 判断、2026-11-19）: LINLEN=80、ゾーン幅
   CLMWID=10 のまま、NCMPOS を 30→**70** に変更（原典自身の公式
   ((LINLEN/CLMWID)−1)×CLMWID 通り）。PRWIDTH の折り返し判定 80 と整合。
   NUMSPC=$20 は不変。

## 設計上の要点（原典との対応）

- **ディスクリプタ形式**は M3 来の 5 バイト（長さ 1＋ポインタ 4）。
  ディスクリプタの「アドレス」は FAC+4..7 のロングワードに載る。
- **PUTNEW のステージング**: 原典は FAC 自身にディスクリプタを置くが、
  本移植の FAC はアドレス保持で埋まっているため、専用スロット DSCBUF に
  ステージングしてから積む（FE_STR/FE_CHR/CAT の 3 経路で共用）。
- **テンポラリスタックの置き場所**: 原典オフセット $9C では INDEX1 まで
  9 バイトしかなく 3 個置けないため、ZP ミラーの空き領域 $180 へ移転
  （TMPDSC）。TEMPPT/LASTPT はバイトオフセットから 4 バイトポインタに変更。
- **評価器フレーム拡張**: RELOPS 用に、積んだ文字列オペランドの
  ディスクリプタアドレスをフレームに 1 ロングワード追加（PERFORM2 が
  ARGDSC に戻す）。同時に、文字列 FAC に対しては ROUND_FAC をスキップ
  （FAC+4..7 はアドレスなので、丸めのシフト/増分で壊れる）。
  文字列に対する '+' 以外の算術演算子は ?TM ERROR（原典の CHKNUM 到達点と
  同じ結果になるよう EV_OPDEC で判定）。
- **PUTSTR の所有権規則**（GC の正しさの要）: 代入元データが文字列領域内
  （>=FRETOP）かつディスクリプタが変数のもの（>=VARTAB）なら、先に新しい
  領域へコピーしてから代入（GC は 1 データブロックにつき 1 ディスクリプタ
  しか更新しないため、変数同士の共有は禁止）。テンポラリなら FRETMS で
  スロットを解放して引き継ぎ、それ以外（プログラム内リテラル等）は共有。
- **直接文リテラルのコピー**: 入力バッファ内（TXTTAB 未満）のリテラルは
  次の行入力で上書きされるため、文字列領域へコピーしてからテンポラリ化
  （原典 STRLT2 のバッファ判定と同じ理由）。プログラム内リテラルは共有。
- **FRETMP の回収条件**は原典通り「データポインタ == FRETOP のとき
  FRETOP += 長さ」（当初「終端 == FRETOP」と読み違え、原典コードで訂正した）。
- **GOSUB フレームの置き方**: FETCH の JSR 戻りアドレスは捨て（GOTOH と
  同じ流儀）、RETURN は EXEC への戻りアドレスを GOSRET に退避してから
  SP を組み替える（FORH/NEXTH の退避スロット方式の踏襲）。

## 照合結果（出口条件）

すべて run_m5a.py で自動判定。期待値 "G" は golden（py65＋CBM BASIC 2）と
バイト照合（$1D→$20 正規化は従来通り、今回の照合では数値末尾の 1 バイトのみ）。

- GOSUB 基本形（SUB→BACK の順序）、2 重ネスト（SUB2→SUB1→BACK1）: **golden 一致**
- A$="FOO", B$="BAR" で PRINT A$+B$+"!" → `FOOBAR!`: **golden 一致**。
  再代入 A$="X" 後の PRINT A$ → `X`: **golden 一致**
- 文字列比較 IF A$="FOO" / A$<>"BAR" / "ABC"<"ABD" / "ABC">"ABD"（偽）/
  "ABD">"ABC" / <= / >= / "="ABC"="ABC": **全て golden 一致**
- GC ストレス 1: `B$=A$+A$+A$+A$+A$`（50 文字）を 2,000 回。1 回あたり
  約 140 バイトのゴミ（中間テンポラリ 20+30+40＋旧 B$ 50）→ 総ゴミ約
  280KB で、文字列領域（移植 61,440／golden 31,743）の数倍。?OM ERROR に
  ならず完走し `SURVIVED` と B$ の中身（"0123456789"×5）が **golden 一致**。
  完走自体が「GC が回った」証明になる量に設定した（回数の調整は不要だった）。
- GC ストレス 2: A$="AL"+"PHA"、B$="BE"+"TA"（＝文字列領域に住む生存文字列）
  を保持したまま `C$=A$+B$+A$+B$+A$+B$` を 900 回（総ゴミ約 82KB、両環境の
  領域超）。GC でデータが移動しても変数ディスクリプタが追随し、最終出力
  `ALPHA-BETA-ALPHABETAALPHABETAALPHABETA` が **golden 一致**
- 蓄積 `FOR I=1 TO 50: A$=A$+"AB": NEXT: PRINT A$` → AB×50（100 文字）:
  **golden 一致**。別途、255 文字ちょうどまで蓄積→もう 1 文字で ?LS ERROR
  も確認
- FRE(0)／FRE("X") → `-4100`（自マップ仕様照合。golden 側は 31,741 等で
  マップ依存のため照合対象外＝当初方針通り）
- 端末幅: 後述の理由でゾーンは全カラム仕様照合。カラム 70 未満では改行せず
  （8 項目が 0,10,…,70 に並ぶ）、70 ちょうどで改行、69 では 1 スペース詰めて
  70 から、31 桁項目＋カンマは 40 桁ゾーンへ詰める（M4 の改行挙動から変更）

## 原典から外れた点

- **GC の配列要素走査は未実装**（配列自体が M5b）。走査順と候補規則は原典に
  合わせてあり、M5b で第 3 走査を足すだけの構造にしてある。
- **GOSUB の CHKMEM（スタック残量チェック）を省略**。原典はフレームを積む
  前に ?OM ERROR 判定をする。本 sim のスタックは深く実害はないが、原典との
  差として明記する。
- **GETSPA の「GC 済み」フラグ**は原典の DATAFLG 流用ではなく専用バイト
  GCSW（GETSPA ローカル）。振る舞いは同一。
- **エラーメッセージは短縮形**（?RG ERROR 等）。golden は長形
  （?RETURN WITHOUT GOSUB ERROR）を出す。M1 からの移植側の慣例であり、
  run_m5a.py では golden 側は長形の部分文字列で「同じ条件で蹴られる」こと
  を確認した。
- **ディスクリプタのパック形式（5 バイト）と奇数アドレスのロングアクセス**:
  ポインタが奇数オフセット（+1）にあり、MOVE.L が奇数アドレスにかかる。
  Musashi sim は許容するが**実機 MC68000 ではアドレスエラーになる**。
  Phase 1（sim 検証）の範囲では形式を維持したが、実機移行フェーズで
  6 バイト形式等への見直しが要る（M5b 以降への引き継ぎに明記）。
- 端末幅 80 桁（NCMPOS=70）は Kyo 判断による意図的な乖離（上記）。

## 踏んだ問題（切り分け記録）

1. **PTRGET の名前エンコーディング（M1–M4 の潜在バグ）**: 従来は全変数の
   第 2 名前バイトに $80 を立てていたため、A（数値）と A$（文字列）が同じ
   スロットを共有していた。文字列変数が無かったので不可視だった。原典は
   $/% の経路だけが $80 を立てるので、それに合わせて修正。GC の変数走査も
   この印（第 1 バイト $80＝整数、第 2 バイト $80＝文字列）で型を判別する。
   修正の確認として `A=5: A$="STR": PRINT A;A$` → ` 5 STR` を golden 照合。
2. **PRINT の PRLIT 近道は原典に無い逸脱だった**: 原典 PRINT2 には
   リテラルの近道がなく全項目が FRMEVL 経由。近道があると後続の '+' が
   見えず `PRINT "A"+"B"` が ?SN ERROR になる。M5a で近道を撤去し原典
   準拠に。副次発見として、M4 の TAB/SPC テストは「OUTSP に D0 を壊された
   PRITEM が偶然 FRMEVL に落ちて」通っていたことが判明。
3. **PRTNXT の D0 喪失（M4 からの潜在バグ）**: TAB/SPC のスペース出力
   （OUTSP）が D0 を書き換えるため、文末の裸の `PRINT SPC(3)` が ?SN ERROR
   になっていた。PRTNXT で CHRGOT し直して修正。
4. **直後ラベルへの BRA（asm68k-py の変位 0 誤符号化）**: PRLIT 撤去で
   PRANEXT が PRSTRG の直後になり、変位 0 の BRA が壊れて ?US ERROR 連発に
   なった。分岐チェッカが 2 件検出。フォールスルーに書き換えて解消
   （TAB の PRTCNT も同型だった）。チェッカ併用の house rule の有効性を再確認。
5. **FE_STR の CHRGET による D0 破壊**: リテラル開始アドレスを D0 に持った
   まま閉じ引用符を CHRGET で読み飛ばし、コピー元が ZP 先頭（ゼロ領域）に
   化けて「長さだけ合った NUL 文字列」を量産した。開始アドレスを CHRGET の
   前に STRNG1 へ退避して修正。切り分けは「プログラム内リテラル（共有経路）
   は正常・直接文リテラル（コピー経路）だけ NUL」で確定した。
6. **ゾーン照合の前提が崩れていた**: 「カラム 30 未満は golden 一致のはず」
   という前提で `PRINT 1,2,3` を照合したら不一致。実測すると golden
   ハーネス（py65）の KERNAL CHROUT スタブはカーソル列を保持しないため、
   カンマのたびに位置無関係に $1D（カーソル右）×10 を吐く縮退挙動だった
   （`PRINT "A","B"` → `A`＋$1D×10＋`B`）。つまりこの golden ではゾーンは
   **どのカラムでもバイト照合できない**（M3/M4 でもゾーンは golden 照合
   されたことがなく、M4 は自前仕様の期待値だった）。よって M5a では
   ゾーン検証を全カラム仕様照合（原典アルゴリズム＋CLMWID=10＋LINLEN=80
   から導いた期待値）に切り替えた。実装側の不具合ではなくハーネスの限界。
7. **run_m4.py の期待値 2 件を更新**（回帰の意味を保つため）:
   31 桁項目＋カンマ（NCMPOS 変更で改行→40 桁ゾーン詰めに）と
   `PRINT "A"+"B"`（?SN ERROR→`AB`、CAT 実装のため）。どちらも変更箇所に
   コメントを付けた。それ以外の M4 検査（ASCIIART バイト一致を含む）は
   無変更で PASS。

## M5b への引き継ぎ

- **配列**: GC に原典第 3 走査（配列要素）を追加すること。PUTSTR の所有権
  規則とディスクリプタ管理は配列要素でも同じ形で必要になる。
- **文字列関数群**（LEN/STR$/VAL/ASC/LEFT$/RIGHT$/MID$）: PUTNEW/FRETMP の
  規律の上に載る。?ST ERROR（テンポラリ枯渇）の到達式は M5a の機能範囲では
  作れなかった（原典でも文字列関数なしでは同様）ので、関数群と一緒に
  到達テストを設計すること。
- 残り: INPUT/READ/DATA の実行時読み、ON...GOTO/GOSUB、PEEK/POKE、
  RESTORE/STOP/CONT、DEF FN、数学パック残り（LOG/EXP/SQR/^、RND、三角関数）。
- **実機移行時の注意**: ディスクリプタのパック形式は奇数アドレスの
  ロングアクセスを含む（上記）。実機フェーズでは形式見直し（6 バイト化等）
  と、それに伴う GC/PUTSTR/CAT の再検証が要る。FRE の値も実機のメモリ
  マップ（MEMSIZ 確定方法）で再確認すること。
- 端末幅は 80 桁で確定済み。以後の PRINT 関連（INPUT のプロンプト表示等）
  も 80 桁前提で設計してよい。
